# 回歸檢核清單

每個動到朗讀、按鈕、版面、練習頁的 PR，開 PR 前逐項自查，PR 描述寫「檢核：已過／不適用／未驗證（原因）」。
發現新的重複問題，就加一條在這裡。

## 朗讀與亮燈
- [ ] 任何會唸整句／整篇的功能都用 `Highlighted` + `speak(..., onProgress)`（卡拉OK亮燈），不要另做一套。
- [ ] **全站規則**：畫面上的外語例句、短文、解說裡的例句，都用 `<SpeakText>` 包起來：點句子就唸那一句＋亮燈，唸完前再點＝暫停，再點＝接著唸。中文夾外語用 `mixed`。新功能預設就要有，不要只放一顆 🔊 讓人找。
- [ ] 朗讀控制只用全站同一組：`SpeakControls`（浮動圓鈕）、`SayButton`、`SpeedButton`，不要在頁面另放重複的播放／暫停／速度。
- [ ] 每一頁有可朗讀內容的地方都有 🔊（聽力題、聽寫、單字卡、短文、跟讀、作業複習、Games）。新增題型先確認。
- [ ] 亮燈相關改動先讀 `docs/speech-karaoke-sync.md`，跑 `npx vitest run`。
- [ ] 慢／一般／快各切換一次不亂跳、不落後；🐇 只標整句。
- [ ] 暫停→繼續從停住的字接著唸，不是整句重來；單句再點一次是暫停不是停止。
- [ ] 換語音的功能用三星瀏覽器驗證（Android Chrome 會忽略指定語音）。

## 按鈕位置與一致性
- [ ] 同一個動作（錄音開始／停止、播放／暫停）在固定位置，不要開始在一處、停止在另一處。
- [ ] 手機（400px）和電腦（1400px）各截圖一次：功能、元件相同，只有版面可不同；浮動鈕用 `dock-right`。
- [ ] 彈出視窗（語音選單等）在窄螢幕不被切掉、不被其他浮動元件擋住（跟讀 🎤、右下圓鈕、Toast）。
- [ ] 六個主題（淺、暗、sage、sand、slate、system）看得清楚。

## 資料與練習頁
- [ ] 結果頁「答對 X / Y」：X 不可大於 Y。題卡的「下一題」／選項要防連點（`ChoiceQuestion`、`SpellQuestion` 只回報一次），答對數由作答紀錄算，`SessionDone` 會用 `clampCorrect` 保底。
- [ ] 配對／選擇題的中文意思不能撞在一起（effect/affect 都寫「影響」）：可以同組出，但要標詞性或提示；統一走 `labelAmbiguousPairs`（`src/lib/games.ts`），AI 出題、題庫、畫面顯示三處都會檢查。
- [ ] 作業複習、跟讀評分、各練習頁入口都還在（改版後逐頁點過）。
- [ ] 有新功能或明顯改進：`src/content/guide.ts` 的 `UPDATES` 最上面加一行小孩看得懂的短句。
- [ ] 需要資料庫欄位：附 SQL 檔，程式在欄位還沒建立時不能壞掉；PR 描述寫 管理者 要跑什麼。

## 回報
- [ ] 明講驗證到什麼程度：單元測試、Playwright 假語音、真手機（哪個瀏覽器）。沒實機驗證就直說。
